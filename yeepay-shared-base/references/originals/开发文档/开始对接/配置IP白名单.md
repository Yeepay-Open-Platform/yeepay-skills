# 配置IP白名单

## 一、什么是IP白名单？

为了提高商户服务器访问API网关的安全性，避免商户因应用私钥泄漏等原因导致业务受损，易宝开放平台提供了 IP 白名单机制，商户可基于该机制对资金操作类敏感接口配置 IP 白名单。

API网关将基于商户配置的 IP 白名单，校验商户请求的来源 IP。

若来源 IP 不在配置的 IP 白名单范围内，则API网关将拦截对应的非法请求。  
  
注意对接以下接口必须配置IP白名单：

/rest/v1.0/balance/yop-group-remit/transfer-confirm  
/rest/v1.0/balance/transfer\_batch\_send  
/rest/v1.0/balance/transfer\_send  
/rest/v1.0/balance/cash

## 二、配置IP白名单

登录【控制台】>【我的应用】>【IP白名单】，进入IP白名单管理页面。

在IP白名单管理页面，可以增加新的IP白名单，也可以修改、删除、查询当前已存在的IP白名单。如果还没有设置过IP白名单，可点击“立即设置”配置IP白名单。

![配置IP白名单1.png](https://open.yeepay.com/attachments/2026/02/02/doc_17KJ0yqVuzI_1770026105621.png)

平台支持部分接口、全部接口两种配置 IP 白名单的方式。部分接口是指您已签约的高风险接口，全部接口是指所有接口（不包含返回302的重定向接口）。

## 六、IP白名单拦截规则

开放平台支持部分接口、全部接口两种配置 IP 白名单的方式。部分接口是指您已签约高风险接口，全部接口是所有接口（不包含返回302的重定向接口）。针对这两种配置方式，开放平台对于

<span style="--un-rotate: 0; --un-rotate-x: 0; --un-rotate-y: 0; --un-rotate-z: 0; --un-scale-x: 1; --un-scale-y: 1; --un-scale-z: 1; --un-skew-x: 0; --un-skew-y: 0; --un-translate-x: 0; --un-translate-y: 0; --un-translate-z: 0; --un-pan-x: 0; --un-pan-y: 0; --un-pinch-zoom: 0; --un-scroll-snap-strictness: proximity; --un-ordinal: 0; --un-slashed-zero: 0; --un-numeric-figure: 0; --un-numeric-spacing: 0; --un-numeric-fraction: 0; --un-border-spacing-x: 0; --un-border-spacing-y: 0; --un-ring-offset-shadow: 0 0 transparent; --un-ring-shadow: 0 0 transparent; --un-shadow-inset: 0; --un-shadow: 0 0 transparent; --un-ring-inset: 0; --un-ring-offset-width: 0px; --un-ring-offset-color: #fff; --un-ring-width: 0px; --un-ring-color: rgba(147,197,253,0.5); --un-blur: 0; --un-brightness: 0; --un-contrast: 0; --un-drop-shadow: 0; --un-grayscale: 0; --un-hue-rotate: 0; --un-invert: 0; --un-saturate: 0; --un-sepia: 0; --un-backdrop-blur: 0; --un-backdrop-brightness: 0; --un-backdrop-contrast: 0; --un-backdrop-grayscale: 0; --un-backdrop-hue-rotate: 0; --un-backdrop-invert: 0; --un-backdrop-opacity: 0; --un-backdrop-saturate: 0; --un-backdrop-sepia: 0; -webkit-tap-highlight-color: rgba(0, 0, 0, 0); font-weight: bolder;">不同场景的校验规则如下：</span>

-   场景1：应用仅配置了部分接口 IP 白名单，API网关针对该应用的接口请求，会判断该 IP 白名单中是否包含请求中的接口。若包含，API网关则以该 IP 白名单校验请求来源 IP。
-   场景2：应用仅配置了全部接口 IP 白名单，API网关针对该应用的所有接口请求，都会使用该 IP 白名单来校验请求来源 IP。
-   场景3：若应用既配置了部分接口 IP 白名单，也配置了全部接口 IP 白名单，API网关针对该应用的接口请求，会先判断部分接口 IP 白名单中是否包含该请求中的接口。若包含，API网关则以命中的部分接口 IP 白名单校验该请求来源 IP，同时忽略全部接口 IP 白名单；若不包含，API网关则以全部接口 IP 白名单校验请求来源 IP。

-   配置1：部分接口IP白名单，接口 /rest/v1.0/std/trade/order，IP配置 192.168.10.1  
    配置2：部分接口IP白名单，接口 /rest/v1.0/std/trade/order，/rest/v1.0/std/trade/orderclose，IP配置 192.168.10.2  
    配置3：部分接口IP白名单，接口/rest/v1.0/std/trade/orderquery，IP配置 192.168.10.3  
    配置4：全部接口IP白名单，IP配置 192.168.10.4

若应用A调用 /rest/v1.0/std/trade/order 的请求来源 IP 是 192.168.10.4，API网关收到该请求后，发现该接口存在以部分接口方式配置的 IP 白名单（配置1、配置2），API网关将只使用命中的部分接口 IP 白名单（配置1、配置2）校验来源 IP，校验结果是来源 IP 不在白名单中，尽管该请求的来源 IP 在该应用的全部接口 IP 白名单中（配置4），但API网关依旧会拦截该请求。
