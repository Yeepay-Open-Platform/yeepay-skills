# 错误码与排障入口

## 错误码两层结构

接口调用返回错误时，错误码分为两层，请按顺序排查：

### 第一层：业务级错误码（优先查）

来源：**当前调用的接口文档自身的“错误码”章节**。

特征：
- 通常以 `00xxx` 等短码形式出现
- 例如：`00012 产品未开通`、`00001 参数错误`、`00201 下单失败`
- 含义和处理建议**因接口而异**，必须看该接口文档

排查步骤：
1. 先确认是哪个接口调用返回的错误（如“聚合支付统一下单”“申请退款”等）
2. 在对应业务域 `references/apis/` 下的接口说明，定位到具体接口的原文文档（`references/originals/...`）
3. 阅读该接口原文里的“错误码”章节，按表格中的“解决方案”执行

### 第二层：平台通用错误码（再查）

来源：`originals/开发文档/开始对接/平台错误码说明.md`

特征：
- 通常以 `40xxx`、`sys.xxx`、`isv.xxx` 等形式出现
- 适用于平台级问题，如鉴权、签名、IP 白名单、限流等

## 处理顺序（推荐）

1. **接口报错** → 先看接口文档自身错误码（业务级）
2. **接口文档查不到** → 再看平台错误码说明（平台级）
3. **仍无法判断** → 走通用排障流程（签名/鉴权/网络/参数）
