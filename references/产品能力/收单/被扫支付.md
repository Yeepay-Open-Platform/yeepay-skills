# 被扫支付（付款码）

**商户扫用户**的付款码完成收款（用户出示微信/支付宝付款码，商户扫码枪/收银台扫描）。

> 接口字段以在线文档为准：按下表 catalog id 在 `../api-index.yaml` 取其 `doc_md` 链接，执行
> `curl -sS "<doc_md>"` 后再实现（单文件含字段/示例/错误码/示例代码）。

## 场景 → 接口

| 用途 | catalog id | 方法 | 路径 |
|------|-----------|------|------|
| 付款码支付 | `aggpay-barcode-pay` | POST | `/rest/v1.0/aggpay/pay` |
| 查单 | `trade-order-query` | GET | `/rest/v1.0/trade/order/query` |

支付结果回调：`aggpay-barcode-pay` 的 `notify_spi: trade.pay-result`。

## 流程

1. 用户打开微信/支付宝出示付款码。
2. 商户扫码取得 `authCode`，后端调 `aggpay-barcode-pay` 提交。
3. 同步响应可能返回**支付中**（需输密码/风控），此时务必轮询查单确认终态。
4. 以「支付结果通知 + 查单」确认终态。

## 必读规则

1. `../../平台文档/平台规范/安全认证/鉴权认证机制(RSA).md`（请求签名）。
2. `../../平台文档/平台规范/安全认证/结果通知(RSA).md`（回调验签）。

## 易错点

- 付款码 `authCode` 有时效，扫码后需尽快提交。
- 同步返回"支付中"不是失败：必须轮询查单，不可立即判失败或重复下单。
- 与主扫区别：被扫=商户扫用户；主扫=用户扫商户。
- 终态以后端为准。
