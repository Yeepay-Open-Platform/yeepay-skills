# 订单分账

基于原交易订单进行分账（依赖一笔已完成的收单交易）。

> 接口字段以在线文档为准：按下表 catalog id 在 `../api-index.yaml` 取其 `doc_md` 链接，执行
> `curl -sS "<doc_md>"` 后再实现（单文件含字段/示例/错误码/示例代码）。

## 场景 → 接口

| 用途 | catalog id | 方法 | 路径 |
|------|-----------|------|------|
| 申请订单分账 | `divide-apply` | POST | `/rest/v1.0/divide/apply` |
| 完结分账 | `divide-complete` | POST | `/rest/v1.0/divide/complete` |
| 查询订单分账结果 | `divide-query` | GET | `/rest/v1.0/divide/query` |
| 申请资金归还 | `divide-back` | POST | `/rest/v1.0/divide/back` |
| 查询资金归还结果 | `divide-back-query` | GET | `/rest/v1.0/divide/back/query` |

## 流程

1. 收单下单时若需分账，传 `fundProcessType` 与 `divideDetail`（见 `../收单/`）。
2. 交易完成后调 `divide-apply` 发起分账，必要时 `divide-complete` 完结。
3. 需退回分账资金时调 `divide-back`。
4. 结果以 `divide-query` / `divide-back-query` 或回调确认。

## 必读规则

1. `../../平台文档/平台规范/安全认证/鉴权认证机制(RSA).md`（请求签名）。
2. `../../平台文档/平台规范/安全认证/结果通知(RSA).md`（回调验签）。

## 易错点

- 订单分账需在交易完成且未结算前发起，规则以在线文档为准。
- 分账方资质与分账比例限制以平台配置为准。
- 资金归还与完结分账的先后顺序按文档状态机执行。
- 分账单号业务唯一，重试用同一单号。

## 排障

- 分账结果以查询接口/回调为准；业务错误码见接口 `doc_md` 的「错误码」章节，平台码见 `../../平台文档/开始对接/平台错误码说明.md`。
