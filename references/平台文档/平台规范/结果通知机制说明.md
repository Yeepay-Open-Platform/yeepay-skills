# 结果通知机制说明

为保证数据的一致性，在交易处理完毕后易宝系统会按照商户调用预下单请求时所传入的异步通知地址参数 notifyUrl，通过 POST 请求的形式将业务处理结果以 FORM 格式通知到商户系统。

#### 通常情况下，只有业务处理成功的订单才会触发异步通知，特殊情况会在具体的异步通知文档中提及。

#### 以下注意事项商户务必要明晰：

1. “幂等性”：同样的通知可能会多次发送给商户系统，商户系统必须能够正确处理重复的通知。“幂等性”：同样的通知可能会多次发送给商户系统，商户系统必须能够正确处理重复的通知。 推荐的做法是：当商户系统收到通知进行处理时，先检查对应业务数据的状态并判断该通知是否已经处理。如果未处理，则进行处理；如果已处理，则直接返回结果成功（http状态码200，报文体SUCCESS）。在对业务数据进行状态检查和处理之前，要采用数据锁进行并发控制，以避免函数重入造成的数据混乱。
2. “时效性”：在极少情况下可能发生异步通知无法正常通知到您服务器的情况，请务必对接主动查单接口。“时效性”：在极少情况下可能发生异步通知无法正常通知到您服务器的情况，请务必对接主动查单接口。 根据业务场景设置合理的请求间隔，比如在支付后1小时还没有异步通知时可以发起主动查单请求。 频繁调用主动查询接口可能触发频度控制、日交易配额等规则导致查询失败，可适当降低查询频率或联系销售、技术支持获得帮助。
3. “防抵赖”：商户系统对异步通知的内容一定要做签名验证，并校验通知的信息是否与商户侧的信息一致，防止数据泄漏导致出现“假通知”，造成资金损失。“防抵赖”：商户系统对异步通知的内容一定要做签名验证，并校验通知的信息是否与商户侧的信息一致，防止数据泄漏导致出现“假通知”，造成资金损失。
4. “兼容性”：异步通知参数列表可能随业务发展进行合理调整（如新增参数、字段顺序变动等），商户系统在解析通知时，请务必：“兼容性”：异步通知参数列表可能随业务发展进行合理调整（如新增参数、字段顺序变动等），商户系统在解析通知时，请务必：

- 避免使用完全匹配校验（如固定字段数量、固定顺序的强校验逻辑）；
- 采用动态解析方式（如通过键值对 Map 或 JSON 对象获取参数，而非依赖字段顺序或固定字段集）；

## 结果通知地址

一般每个接口中会提供异步通知地址参数，通常为 notifyUrl。

商户也可以在开发者中心配置异步通知回调地址。当请求api时没有传递回调地址参数同时需要异步通知时，易宝会采用该默认的回调地址进行异步通知处理。

## 结果通知频率

如果商户未按正常处理做出应答（http状态码200，报文体SUCCESS），易宝将认为该次通知是失败的，间隔一定时间后会尝试再次通知。

一般情况下，24小时以内会完成多次异步通知（通知的间隔频率一般是：5s、10s、15s、30s、240s、600s、2700s、3600s、14400s，即易宝处理成功后的 5s、15s、30s、1m、5m、30m、1h30m、5h30m）。

#### 注意：

1. 易宝可能根据系统负载和业务情况，在不通知商户的情况下调整异步通知的时间间隔和次数，请勿根据该时间间隔和次数做业务处理。易宝可能根据系统负载和业务情况，在不通知商户的情况下调整异步通知的时间间隔和次数，请勿根据该时间间隔和次数做业务处理。
2. 异步通知是最大可能交付，但不排除失败的情况。请务必对接主动查询接口，在合理的时间间隔后主动请求对应的查询接口（频繁调用可能受到配额限制）。异步通知是最大可能交付，但不排除失败的情况。请务必对接主动查询接口，在合理的时间间隔后主动请求对应的查询接口（频繁调用可能受到配额限制）。
3. 易宝对商户侧的连接和读取超时时间均为5秒，请尽可能在此时间内返回结果，否则可能会导致延迟通知或重复通知。易宝对商户侧的连接和读取超时时间均为5秒，请尽可能在此时间内返回结果，否则可能会导致延迟通知或重复通知。

## 结果通知报文处理与应答

根据使用的密钥类型，商户侧收到的报文格式和解密验签方式存在细微差异。

- 国际密钥（RSA）请参见 [国际密钥(RSA)异步通知](https://open.yeepay.com/docs-v3/platform/207.md)
- 国密密钥（SM）请参见 [商密密钥(SM2)异步通知](https://open.yeepay.com/docs-v3/platform/3926.md)

## 最佳实践

针对一个商户应用部署一套异步通知接收网关，由该网关根据异步通知报文交由不同的处理器处理具体业务逻辑。
