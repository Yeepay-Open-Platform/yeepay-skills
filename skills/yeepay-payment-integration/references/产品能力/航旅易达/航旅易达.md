# 航旅易达（机票，Ticket Service PRO）

航旅易达（Ticket Service PRO，TSP）是聚合多种机票渠道、以统一完善的接口流程和定义提供服务的接口产品，TMC/机票代理等合作伙伴可高效便捷地开展机票资源对接。

- 支持商户获取准确完整的机票价格、服务、使用规则等信息，用来直接服务旅客出行的机票预订和后续服务，或通过相关信息的提供，赋能商户的作业流程。
- 产品功能覆盖机票的**出票、退票、改升全流程**，支持航班价格查询、退票价格查询、改升价格查询、订单查询等基础业务功能，及电子行程单、客票状态查询等附加功能。

> **文档来源与其他业务域不同**：航旅易达按「渠道（解决方案）」组织文档，**不适用** `docs-v3/api/<slug>.md` 的 slug 推导规则。
>
> - **适用场景**：以各渠道的**产品介绍** md（`https://open.yeepay.com/docs-v3/solution/hlyd-*/<id>.md`，可直接 curl，含适用场景表）为准；**须先读产品介绍，再读接口调用指引**。
> - **业务链路**：以各渠道的接口调用指引 md（可直接 curl，含接口调用顺序矩阵）为准。
> - **接口规格**：以各渠道的接口 openapi.json（`https://open.yeepay.com/apis/docs/solutions/hlyd-*/<hash>/openapi.json`，可直接 curl，含字段/错误码/示例代码）为准。
> - 人类可读的「接口调用指引」页（`docs-v3/solution/hlyd-*/guide/<id>`）为 SPA，curl 取不到内容，仅供人工浏览。
> - curl 失败（403/404/超时）时不得臆造字段与链路，提示检查网络后停止字段级实现。
>
> 渠道与接口清单见 `渠道API清单.md`。

## 环境与安全约束（最高优先级）

- **无沙箱环境**：航旅易达接口**没有沙箱环境，所有接口调用均在生产环境进行**；出票/退票/改签均为真实业务操作。任何实际调用前必须按 `SKILL.md` 面客纪律④执行**生产环境显式二次确认**。联调建议从查询类接口（航班查询、订单查询）开始小步验证；写操作（出票/支付/退票/改签）须经商户明确授权后再执行。
- **敏感信息保护**：提示商户**不要在对话中直接向 Agent 透露敏感信息**，包括：乘客信息（姓名、证件号）、联系人电话、支付账号信息、密码、航司 B2B 账号等。生成代码与示例报文时一律使用占位符（如 `<乘客姓名>`、`<证件号>`、`<B2B账号>`），由商户在自有环境中填入真实值。

## 渠道决策（选哪种）

```text
客户具备什么资源/诉求？
├─ 没有航司 B2B 账号 ─────────────────► NDC2C 对接（南航/厦航/山航/深航/昆航/国航 NDC2C）
├─ 有航司 NDC2B / NDC2T 授权 ─────────► NDC2B/NDC2T（南航/厦航/深航 NDC2B、东航 NDC2T）
├─ 仅有航司 B2B 账号、无 NDC2B 授权 ──► 航司 B2B（东航 B2T、厦航 B2B、南航 B2B 国内/国际、港航 B2B）
├─ 想采购分销渠道 ───────────────────► OTA 分销渠道（美团、航班管家、蜗牛/去哪儿、京杭、51BOOK 等）
└─ 有 CDP 账号 ──────────────────────► 易宝 CDP 渠道
```

判定要点：

- **NDC2C / NDC2B / NDC2T / B2B 不可互换**：分别对应不同的渠道编码与接口目录，客户只报航司名称时须先澄清其账号/授权情况。
- 同一航司可能同时存在多种模式（如南航有 NDC2C、NDC2B、B2B 国内、B2B 国际），务必确认渠道编码与航程类型后再定位接口；南航 NDC2C 的国内来回程接口包含在南航 NDC（`hlyd-nhndc`）内，不是独立解决方案。
- 锁定渠道后**先 curl 该渠道「产品介绍」确认适用场景**（单程/往返/来回程、国内/国际、旅客类型、是否支持退改等），再读接口调用指引；具体链接与 API 见 `渠道API清单.md`。

## 附加能力说明

- **政策池**：易宝提供的**航司政策缓存**，用于避免商户频繁直连航司查政策而受到航司侧限制。具体支持渠道与调用说明以接口描述为准（见 `渠道API清单.md`「政策池支持情况」及对应 openapi.json）。
- **电子行程单**：机票报销凭证/开票诉求通常引导至**电子行程单**相关接口（开具、红冲、重新发送、开具/红冲详情查询，见 `渠道API清单.md`「辅助接口」）；不要按通用增值税发票产品处理。电子行程单是机票报销凭证，不等于税务意义上的增值税发票。

## 业务流程

对接任一渠道时，**文档阅读顺序强制如下**（不得跳过适用场景确认直接生成调用链/代码）：

1. **产品介绍（适用场景）**：curl 目标渠道「产品介绍」md，核对航程类型（单程/往返/来回程/中转）、国内/国际、旅客类型、是否支持出票/退票/改签/政策池等，确认与商户诉求匹配。
2. **渠道配置（若有）**：curl「渠道配置说明」，指导商户完成配置或确认已完成（Agent 不能代完成）。
3. **接口调用指引**：curl「接口调用指引」，按其中的接口调用顺序矩阵执行；典型链路仅供理解，**以该渠道指引为准**：
   - 出票：航班查询 →（验舱）验价 → 出票创建订单 → 出票订单支付 → 查询出票订单
   - 退票：查询退票费详情 → 退票申请 → 查询退票订单
   - 改签：改签航班查询 → 改签申请 → 改签支付 → 改签订单查询
4. **接口规格**：字段级实现前 curl 目标接口 openapi.json。

补充说明：

- 部分渠道的同一场景存在**两种调用方式**（如南航 NDC2C 的往返直飞出票）：区别在于调用接口数量不同，取决于代理侧掌握的信息——若能满足「验舱验价（外部）」的入参要求（参数相对多），可选择调用顺序更简单的链路；以南航 NDC2C「产品介绍」+「接口调用指引」为准。
- **南航 NDC2C 的 API 分两组**（见 `渠道API清单.md` 该节【南航NDC】/【南航NDC国内来回程】，**来回程 = 往返**）：接口调用指引中**往返直飞**场景的接口一律取【南航NDC国内来回程】分组的 API，单程等其他场景取【南航NDC】分组；两组同名接口的 openapi.json 不同，不可混用。
- 交易终态以**订单查询接口**确认，不以同步响应为准；超时/未知结果先查单，避免重复出票/退票/改签。

## 接入步骤

1. 确认本次对接的易宝商编，不清楚时找销售确认。
2. 下载基础 SDK：
   - SDK 下载：`../../平台文档/工具与支持/开发工具/平台SDK.md`（各语言 SDK 仓库定位）
   - SDK 使用：`../../平台文档/开始对接/SDK使用说明.md`（Java SDK 配置与调用）
3. 确认对接渠道（渠道编码见上表）。
4. 打开 `渠道API清单.md` 中目标渠道小节，**按顺序**：
   1. curl「产品介绍」，确认适用场景匹配；
   2. 若有「渠道配置说明」，curl 读取并指导商户完成配置/确认配置已完成（配置通常需商户后台、运营、客户经理或航司侧动作，Agent 不能代完成）；
   3. curl「接口调用指引」与接口清单。
5. 按接口调用指引实现业务链路；字段级实现前 curl 目标 openapi.json。
6. 在生产环境调试接口并适配自有系统（无沙箱）；对接问题联系技术支持，运营问题联系大客户运营。

## 易错点

接入实现时必须遵守的约束（生成参数/代码前必读）：

- **无沙箱，全生产**：不要按支付类产品的「先沙箱再生产」流程引导；写操作一律按生产二次确认。
- **先产品介绍、后调用指引**：实现前必须先 curl 目标渠道「产品介绍」核对适用场景；场景不匹配不得套用该渠道接口。再读「接口调用指引」与 openapi.json。
- **渠道配置前置**：部分渠道在 `渠道API清单.md` 对应小节标有「渠道配置说明」；Agent 须先 curl 读取说明，指导商户完成配置或确认配置已完成后再对接接口，不可自行代完成配置。
- **请求体格式**：航旅易达接口均为 NDC 风格请求，`content` 须为 **JSON**，不是 form 表单。
- **验舱验价结果回传**：出票/创单时的 `cabinPriceId`、`cabinPriceItemId` 必须传**验舱验价接口返回**的值，不能传获取政策时的入参；创单前须先完成验舱验价。
- **`travelMark`**：验舱验价、退票等接口常需传行程类型；国内传 `D`。漏传会走到错误链路（如南航国际票逻辑）或报错。
- **乘机人顺序**：创单时 Passenger 同时含成人+儿童，须将**成人放在 List 第一位**（航司侧会员号校验）。
- **证件类型**：目前只支持**身份证和护照**，其他类型可先预留枚举、待后续支持。
- **`payInfos` 类型与加密**：类型为 `List<String>`（不是对象）；明文可不加密；若加密，三个请求参数**整体加密**后写入 `content`（见 `../../平台文档/平台规范/安全认证/报文加密机制(SM).md` / `报文加密机制(RSA).md` 与 `../../平台文档/开始对接/SDK使用说明.md`）。
- **SDK 超时**：与航司交互耗时长，建议将 SDK 读超时从默认 30000ms 调整为 **60000ms**。
- **Python SDK**：JSON 请求须用 `client.post_json(api, post_params=params)`（`application/json`），否则易报 content-sha256 校验失败。
- **查定比**：山航 NDC、厦航 NDC 是否有查定比限制，具体咨询运营。
- **南航（CZ）国内单单减（DLJ）**：使用验价返回的询价 id + 询价详情 id。
- **订单查询字段**：未出票完成的订单不返回航段/行李信息；出票完成后才会返回。
- **机票开票 / 报销凭证**：通常引导至电子行程单接口，勿按通用增值税发票产品处理（见上文「附加能力说明」）。

## 排障

通用路径：

- 业务错误码：见各渠道接口 openapi.json / 接口调用指引中的错误码定义。
- 平台错误码/验签：`../../troubleshooting.md`、`../../平台文档/开始对接/平台错误码说明.md`。
- 渠道类报错（含 `channelErrorMsg`）多为航司/渠道侧返回，先核对易错点中的入参约束（`travelMark`、`cabinPriceId`/`cabinPriceItemId`、`payInfos` 类型等），再联系技术支持。

### 按现象排查

**验价 / 创单 / Offer 相关**

| 现象 | 处理 |
| --- | --- |
| 「验价结果的缓存中不存在指定的 Offer」/「OfferItemRefID can not be empty」/ CDP「is not a valid value for 'NCName'」 | `cabinPriceId`、`cabinPriceItemId` 须传验舱验价返回值，不能传政策查询入参 |
| 「No offerPrice cache, please try offerPrice again」 | 创单前未调用验舱验价 |
| 「System can not reach, please try again later」 | 检查必填字段，尤其 `travelMark`（国内传 `D`） |
| 「not retrievePersonalFlightInfo api response」/ 价格失效 | 重新查询政策并重新下单 |
| 「票价索引返回对象(fareXx)为空」 | 航司接口波动，稍后重试或重新询价 |

**出票 / 支付**

| 现象 | 处理 |
| --- | --- |
| 「服务不可用」 | 确认 `content` 为 JSON 而非 form |
| 「参数类型非法: payInfos」 | 按文档传 `List<String>`，不是对象 |
| 「异常旅客订单…不能重复预定」 | 乘客侧或商户侧重复预定，过不了厦航校验 |
| 「乘客证件类型、乘客类型有误」 | 目前仅身份证/护照 |
| 「数据库不存在该 packOrderNo」 | 成人+儿童时成人须在 Passenger 列表首位 |
| SDK `Read timed out` / `YopUnknownException` | 超时调至 60000ms |
| Python「content-sha256验证失败」 | 改用 `post_json` |

**退票 / 改签**

| 现象 | 处理 |
| --- | --- |
| 「当前通道不支持查询退票费详情」/「CZ退票TicketId传入有误」 | 检查并传入 `travelMark`（国内 `D`） |
| SC「传入ticketId有误」 | 检查是否传入 `travelMark`（未传会报该错误）；或确认 `ticketId` 是否为出票后返回值 |
| 「不允许航程变更」等改签失败 | 多为航司侧资源不足，重新查询可改签航班 |

**配置 / 账号**

| 现象 | 处理 |
| --- | --- |
| 「商户后台未配置航司账号信息」 | 在易宝商户后台配置，或联系易宝运营 |
| 「请配置平台商账号信息」（航班管家） | 邮件配置商编 + client_id + client_secret（主题「航旅易达配置航管ID和密钥」），联系大客户运营获取配置邮箱 |
| 「customerSign错误」 | 联系运营配置商户标识；新商编需确认老 B2B 密钥是否已配置 |
| 厦航 NDC2B「Please contact the airline to configure admittance」 | 确认 `orgid` 已申请，联系销售 |
