# 网联一键绑卡支持银行（速查）

一键绑卡（`frontcashier-bindcard-netsunion-request`）**按银行逐家接入**，各银行支持的**前端形态**（APP/H5）与**卡种**（借记卡/贷记卡）不同。接入前先在本表确认目标银行是否可用，再按 `协议支付.md`「一键绑卡」实现。

> **本表为对客版清单的快照，银行接入情况会随时间变化**：以商户实际开通结果与客户经理/运营确认为准；表中未列出的银行不代表一定不支持，需单独确认。不要凭本表向商户承诺上线时间。
>
> 状态含义：`已商用` = 可直接接入；`待测试上线` = 银行侧在途，暂不可用于生产；`银行暂不支持` / `-` = 该卡种当前不支持一键绑卡。

## 选型要点

- **只有招商银行是纯 APP 形态**，工商银行支持 APP 与 H5，其余 18 家均为 H5。若商户是纯 APP 场景且目标银行只支持 H5，需在 APP 内以 WebView/浏览器承载 H5 跳转，前端方案要提前确认。
- **贷记卡覆盖明显窄于借记卡**：中国银行、招商银行、邮储银行、北京银行明确不支持贷记卡；工商银行贷记卡仍为待测试上线；光大、南京、恒丰、兴业、民生、渤海六家贷记卡状态为 `-`（未标注支持）。做信用卡类业务前先确认卡种。
- **工商银行的通知链路与其他银行不同**：前端通知不返回 `bindId`，须继续走短验重发 → 短验确认 → 后端异步通知，详见 `协议支付.md`「一键绑卡的通知对接逻辑」。
- **银行编码取本表 `银行编码` 列**，但具体参数名与取值以接口 doc_md 为准（`../api-index.yaml` 中 `frontcashier-bindcard-netsunion-request` 的 `doc_md`），不要凭本表拼参数。
- 目标银行不在表内、或需要的卡种/形态不支持时，走四要素签约绑卡（`frontcashier-agreement-sign-request`）作为替代路径。
