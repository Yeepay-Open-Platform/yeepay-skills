# 离线 L1：无诊断凭证时的排障边界

未连接平台排障服务（无诊断凭证、凭证过期/已吊销、远端不可用）时，本技能只能做 **L1 自查建议**。本文规定这一态下的可做、不可做与话术。

结论强度按 `knowledge-map.yaml` 的 `evidenceRequired` 判定；输出用 `SKILL.md` 的 **D1 模板**。

## 一、可以做

- 读 `references/` 给检查建议与自查顺序（`references/troubleshooting.md`）。
- **查平台公开知识库**（`scripts/diag/diag_knowledge.py search|get`）：匿名接口，不需要凭证。检索在本机做（服务端没有搜索端点），商户的问题描述不外发。查到的内容仍是 L1，照样带徽标。
- 解释错误码含义（`references/平台文档/开始对接/平台错误码说明.md`）。
- 解释平台规则：签名/验签、回调机制、密钥与证书、IP 白名单、回调网络。
- 用本地脚本验证**用户自己的测试密钥**（`scripts/`），并显式说明这是本地验证、与平台实时数据无关。
- 提示通知类问题可到控制台「开发服务 > 结果通知」自行查询/重发（这不是诊断凭证）。
- 复述用户**已经贴出**的控制台画面上的可见字段，并标明来源不是平台诊断。
- 说明需要平台实时数据时，用 AppKey + 私钥文件路径在本机兑换诊断凭证（仅对 `evidenceRequired: true` 的条目提这一句，且应在**查过公开知识库仍不够**之后才提）。**不得**说去开放平台或「接入诊断」兑换。

## 二、不可以做

- 声称查过该商户的数据——**查过公开知识库不算查过平台**，那是文档知识，不是这个商户的实时事实。
- 给出事实性陈述，如「你的通知已发送 3 次」「平台侧没收到这笔请求」。
- 编造证据标识（`[ev_x]` 只能来自平台实时诊断结果）。
- 把本地推测标成生产根因。
- 输出「更可能是 / 按概率 / 最可能原因（按优先级）」式原因列表——那是无证据强结论，D1 只保留自查步骤。
- 把用户贴的控制台截图说成平台诊断，或改写 D1 徽标。
- 把 `yop-notifier.biz.*` 等子系统码映射成公开目录里的 `isv.*`。
- 主动索要发送记录截图、完整报文、私钥。
- 为了「帮你验签看看」引导用户粘贴私钥、完整报文、证书正文。
- 把开放平台「开发服务 > 接入诊断」说成诊断凭证兑换入口。接入诊断页是产品/API 开通检查；**诊断凭证只能在本机用 AppKey + 私钥路径兑换**，开放平台网页目前不能兑换。

## 三、话术

**开头（固定徽标）**

```text
〔本地知识 · 未连接平台实时数据〕以下为自查建议，不能作为生产根因。
```

**`evidenceRequired: true` 的条目**：给自查顺序，并明确哪些部分需要平台实时数据才能确认。

> 以下几步您可以先自查。是否是平台侧原因，需要该笔请求的实时事实才能确认——本地看不到这部分。

**`evidenceRequired: false` 的条目**（知识指导类，如应用标识不正确、环境地址、SDK 用法）：直接给完整答案并结束，**不要**再劝用户去连排障服务。

**远端不可用时**：说明当前连不上平台排障服务、已退回本地自查建议，并给出工单预览（`diag_ticket.py` 默认 dry-run）；**不要**用本地推测填补远端结论。

## 四、控制台跳转（本期仅预留，不实现）

本期**不生成**带参跳转链接。无凭证时通知类问题可提示控制台「开发服务 > 结果通知」自行查询，**不要**把「接入诊断」说成排障会话入口或凭证兑换入口。

**开放平台目前不提供诊断凭证兑换。** 兑换只在 IDE：`diag_auth.py` + AppKey + 私钥文件路径。控制台「接入诊断」是另一项能力（检查产品/API 开通），与诊断 token 无关。

将来若实现带参跳转，按此约定，不要另起一套：

- 参数名与 `diagnostic-protocol.md` 的槽位白名单**同源**，逐字一致，两处不得各写一套；
- 只带非敏感槽位（环境、错误码、接口路径、发生时间），不带凭证、不带业务标识；
- 跳转与兑换诊断凭证是**两条独立流程**：跳转不产生凭证、不回传任何东西给 IDE，不得把它描述为获取凭证的步骤。

## 五、与远端态的关系

| | 离线 L1 | 平台实时诊断（L2） |
| --- | --- | --- |
| 结论强度 | 自查建议，话必须弱 | 可贴服务端 `conclusion` 原文，并附证据表 |
| 知识来源 | 本地 `references/` + 平台公开知识库（匿名） | 平台按凭证查到的该商户实时事实 |
| 槽位清单 | 本地 `knowledge-map.yaml` 的 `slots`（兜底） | 服务端 `needInfos`（权威，一次性问全） |
| 证据 | 无，且不得编造 | 有，逐条带标识、来源、观察时间 |
| 输出模板 | D1 | D2 |

远端可用时，本地条目只做补充解释，**不参与结论**。

但「远端可用」不等于「每次都走远端」：`evidenceRequired: false` 的条目即便持有诊断凭证，也在本地答完就收——它们本来就没有对应的实时数据可查，上远端只会白等几十秒再拿一个 `转人工`。判定见 `SKILL.md`「先本地，后远端」。
