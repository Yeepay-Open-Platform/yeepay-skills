# 排障与上线（汇总）

本文件汇总各业务域排障、回调问题、错误码定位、对账差异处理与上线检查。**回调验签/上线规则为本地权威，不走 curl**；接口业务错误码走 curl。

## 一、错误码两层定位

接口返回错误时按顺序排查：

1. **业务级错误码（优先）**：当前调用接口自身的错误码。
   - 在 `产品能力/api-index.yaml` 找到该接口的 `doc_md` 链接。
   - `curl -sS "<doc_md>"`，查看「错误码」章节，按说明处理。
   - 形如 `00012 产品未开通`、`00001 参数错误`，含义因接口而异。
2. **平台级错误码（再查）**：鉴权/签名/IP/限流等平台问题。
   - 本地：`平台文档/开始对接/平台错误码说明.md`。
   - 形如 `40xxx`、`sys.xxx`、`isv.xxx`。
3. **仍无法判断**：走下方通用排障（签名/鉴权/网络/参数）。

## 二、回调问题排查

常见：回调收不到 / 验签失败 / 重复通知 / 与查单状态不一致。

规范来源（本地）：
- `平台文档/平台规范/安全认证/结果通知(RSA).md`
- `平台文档/平台规范/安全认证/结果通知(SM2).md`
- `平台文档/平台规范/结果通知机制说明.md`

排查顺序：
1. 回调地址与网络可达性：`notifyUrl` 是否公网可达、是否被网关/防火墙拦截；商户防火墙是否已放行易宝出口（见 `平台文档/平台规范/回调网络配置.md`）。
2. 验签规则与密钥配置：`平台文档/平台规范/安全认证/鉴权认证机制(RSA).md`；公钥/证书与环境是否匹配。
3. 回调报文是否与验签输入一致（字段、编码、顺序）。
4. 回调处理幂等：重复通知不得重复入账。
5. 控制台 **结果通知** 页可查询/重发通知（见 `平台文档/平台规范/结果通知查询与重发.md`）。
6. 最终状态以查单兜底确认（回调与查单不一致时以查单为准）。

## 三、签名/验签失败

- 核对密钥配对关系（商户私钥 / 平台公钥）。
- 核对签名串拼装、参数排序与 UTF-8 编码、URL 安全 Base64。
- 核对 `x-yop-content-sha256` 计算规则（GET 对空串、POST+JSON 对完整体、form 对非文件参数排序编码；**form 无参数时须对空串 `""` 计算摘要**）。
- Java SDK 用户：查 `平台文档/开始对接/Java-SDK报错说明.md`（含 env=qa、软算法包、BC 版本、HTTP 204 等案例）。
- 详见 `平台文档/平台规范/安全认证/`。

## 四、入网排障

- 同步返回商编 ≠ 入网成功：以「入网结果通知」（`mer.register-result`）业务状态 = **已完成** 为准；未完成的商编无法发起交易、变更等后续操作。
- 审核驳回：从入网结果通知或 `mer-register-query`（入网进度查询）获取驳回原因，修正后重新提交；换请求号会生成新商编，仅参数格式类校验失败允许复用原请求号。
- 图片资质报错：确认已先走 `merchant-qual-upload`（文件上传）转为资质存储 URL；该 URL 外网不可访问属正常现象。
- 聚合支付产品开通后交易受限：确认微信/支付宝实名认证是否完成（`mer-auth-state-query` / `mer-alipayauth-query` 查询，见 `产品能力/入网/实名认证.md`）。
- 商户被冻结：仅**沉默商户**可通过 `mer-dispose-unfreeze` 自助解冻，其他冻结类型联系运营/技术支持。
- 详见 `产品能力/入网/入网.md` 的「易错点」与「排障」。

## 五、收单排障

- 同步返回"支付中"不是失败（被扫/风控场景）：轮询查单确认，勿重复下单。
- `userId`/`openId` 报错：确认 `openId` 基于支付用 `appId` 获取。
- `prePayTn` 唤起失败：按 `产品能力/收单/prePayTn唤起方式速查.md` 确认 `payWay + channel + scene` 对应的返回类型与唤起方式（catalog `prepay-tn-usage`）。
- 终态以「通知 + 查单」为准。

## 六、前端对接问题

APP 拉起小程序、小程序内支付或 WebView 出现无法唤起、无法回跳、返回参数缺失等问题时：

1. 先确认**端上返回结果不是交易终态**；结果通知与查单构成双通道确认机制，任一通道可确认单笔状态，系统须同时具备两种确认能力。
2. 按端类型、微信/支付宝平台和报错原文定位，详见 `平台文档/工具与支持/前端对接问题.md`。
3. 未解决时提供 `orderId`、端类型、平台与系统、`payWay` / `scene` / `launchSource`、报错原文；不要提供完整私钥等敏感信息。

## 七、退款/出款排障

- `account`（账户）、`balance`（代付代发）分组接口（如提现 `/rest/v1.0/account/withdraw/order`、代付 `/rest/v1.0/balance/transfer_send`）调用被拒或报签名/权限类错误：先确认应用密钥是否为 **CFCA 证书**——该两个分组的资金出款类接口必须使用 CFCA 证书签名，普通 RSA 文本密钥会被平台拒绝；同时确认 IP 白名单已配置。见 `平台文档/接入准备/密钥管理/CFCA证书介绍.md`、`平台文档/开始对接/配置IP白名单.md`。
- 状态长期不变：先查询接口核对状态机，再查回调是否到达。
- 写操作（退款/结算/提现）单号业务唯一；重试用同一单号，**严禁重复出款**。
- 超时/未知结果：先查后重试。

## 八、金融（放款 / 信用卡还款 / 协议支付）排障

- **放款取文件勿混用**：**账单** `financial-trade-bill-download` 走 **yos** 文件流 download；**电子回单** `financial-receipt-get` 走 **rest** JSON（`data` 为 Base64 + `fileTypeSuffix`），须解码落盘，**不是** yos download。协议支付回单 `trade-receipt-download` 才是 yos 直下载。
- **查不到订单**：先确认协议支付版本是否用错——1.0 下单（`cnppay-agreement-pay-request`）只能用 `cnppay-query` 查，2.0 下单（`financial-order-pay-request`）只能用 `financial-order-pay-query` 查，交叉使用会返回订单不存在。
- **扣款报签约关系不存在/校验失败**：核对 `bindId` 与 `userType`/`userNo` 是否与绑卡时完全一致、是否属于同一 `merchantNo`；不上送用户标识的用法需与易宝单独配置。
- **签约失败**：核对四要素是否与银行侧一致；信用卡是否漏传 `cvv2`/`validthru`；是否缺**挂网协议**或产品未开通（一键绑卡与四要素绑卡均需挂网协议）。
- **一键绑卡拿不到 `bindId`**：工商银行前端通知不返回 `bindId`，须继续走短验重发 → 短验确认 → 等后端异步通知；非工行前端通知直接带 `bindId`。
- **信用卡还款收不到通知**：该接口**仅异步终态回调，同步响应已是终态时不回调**；先确认是否同步终态，再查回调网络与验签。通知编码须以 doc_md/技术支持确认，不得臆造 SPI。
- **放款被拒或报配置类错误**（`00605` 协议关系不存在 / `00608` 商户配置信息错误 / `UA00014` 未开通付款产品）：确认已按银行完成**对公户报备**与三级产品开通。
- **放款参数报错**：最常见是付款卡与收款卡颠倒——`remitCardInfo`（付款方=资金方）订单付款业务下只支持 `CORPORATE`，`receiverCardInfo`（收款方=借款人）支持 `DEBIT`/`CORPORATE`；联合贷另注意 `remitCardInfoList` 为数组、`notifyUrl`/`clientIp` 必填、`bankCode=ICBC` 时 `merchantSubLedgerId` 必填。
- **处理中不是失败**：`00105 订单处理中`、`UA30001 系统繁忙`、还款 `PROCESSING` 一律**先查单**，禁止换单号重发；终态以「结果通知 + 查询」双通道确认。
- **成功后仍需关注冲退**：放款 `reversed`/`reverseTime`、信用卡还款 `repaymentReverseTime` 有值即已冲退，账务与对账需支持回滚。
- **退款卡在中间态**：开通「补充卡信息退款」后，原路退款失败会停在等待商户补卡状态，需调 `trade-refund-supply` 补卡或 `trade-refund-end` 结束退款；未开通时失败资金自动退回商户易宝账户。
- 现象级约束见 `产品能力/金融/放款.md`、`产品能力/金融/信用卡还款.md`、`产品能力/金融/协议支付.md` 的「易错点」与「排障」。

## 九、航旅易达（机票）排障

- **无沙箱**：接口均在生产环境；联调从查询类接口起步，写操作须生产二次确认。
- 渠道类报错（含 `channelErrorMsg`）多为航司/渠道侧返回；优先核对 `travelMark`、`cabinPriceId`/`cabinPriceItemId`（须来自验舱验价）、`payInfos` 类型（`List<String>`）、请求 `content` 是否为 JSON。
- 机票报销凭证/开票诉求通常引导至电子行程单接口；不要按通用增值税发票产品处理。
- 现象级排查表见 `产品能力/航旅易达/航旅易达.md`「排障」；接入约束见同文件「易错点」。

## 十、对账差异处理

- 以易宝账单为基准与商户流水勾兑；差异分类：己方多 / 己方少 / 对方多 / 对方少 / 状态不一致。
- 单笔差异回到对应业务域用查询接口核实终态后再调整。
- 注意账单生成时延、`yos` 与 `openapi` 网关区分、金额单位与符号。

## 十一、上线检查清单（关键项，未通过不建议上线）

- [ ] 测试与生产参数完全隔离（**航旅易达无沙箱**，该项改为：生产密钥/商编仅用于授权后的生产联调，写操作有二次确认与回滚预案）。
- [ ] 请求签名、回调验签联调通过。
- [ ] 回调处理具备幂等能力（重复通知不重复入账）。
- [ ] 支付/退款/分账/出款均可通过查询接口确认终态；金融域放款、协议支付、信用卡还款以对应查询接口确认终态并支持冲退回滚；航旅易达以订单查询确认出票/退票/改签终态。
- [ ] 关键日志已脱敏，不输出密钥与完整敏感标识（卡号/证件号/乘客信息）。
- [ ] 异常重试策略明确（先查状态再重试）。
- [ ] IP 白名单/回调网络已配置（`平台文档/开始对接/配置IP白名单.md`、`平台文档/平台规范/回调网络配置.md`）。
- [ ] 回滚预案与责任人明确。
- [ ] `api-index.yaml` 中相关接口的 `doc_md` 已 `curl` 可达；航旅易达另确认目标渠道 openapi.json 可达。

> 详尽上线规范见 `平台文档/平台规范/上线前检查清单.md`。
