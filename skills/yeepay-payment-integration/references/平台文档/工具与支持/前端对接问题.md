# 前端对接问题

本文聚焦 APP 拉起小程序、小程序内支付及 WebView 的支付唤起与回跳排障，不替代具体支付接口文档。

两条原则：

1. **端上返回结果不是交易终态**。结果通知与查单构成双通道确认机制：任一通道可确认单笔状态，接入系统须同时具备两种确认能力；物理键返回、取消无返回参数时主动查单，不要重复拉起同一订单。
2. 未解决时请提供 `orderId`、端类型（APP / 小程序 / WebView）、平台与系统、`payWay` / `scene` / `launchSource`、报错原文；不要提供完整私钥、AppKey Secret 等敏感信息。

> 标注为“经验排查方向”的条目来自接入经验，不能替代接口错误码、查单结果、结果通知或平台日志。

## 一、APP 拉起小程序支付

### 微信

#### Android 调用 `sendReq` 无反应

- **原因**：常见为微信 ID 混用或开放平台关联关系错误。
- **处理**：`appId` 使用微信开放平台“移动应用”的 AppId（`wx` 开头），`userName` 使用小程序原始 ID（`gh_` 开头）；确认移动应用与小程序已在同一开放平台账号下关联。可对照[微信 Android 拉起小程序示例](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Launching_a_Mini_Program/Android_Development_example.html)。

#### iOS 调用 `sendReq` 返回 `success=NO` 或无反应

- **原因**：可能是产品前置条件、目标小程序参数、Universal Links 或微信 OpenSDK 接入不完整。
- **处理**：
  1. 确认移动应用与目标小程序已正确关联，支付产品已开通并完成微信侧报备、实名认证。
  2. 使用易宝收银台小程序最小链路验证：`userName=gh_75b350055f04`、`path=pages/fromAppPay/index`、正式版环境。
  3. 再替换为商户自己的小程序，区分商户配置问题与基础拉起链路问题。
  4. 确认 Universal Links 能拉起主 APP，并已实现 `WXApiDelegate` 的 `onReq:` / `onResp:`。详见[微信 iOS 接入指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/iOS.html)。

#### 提示“由于应用 universal link 校验不通过”

- **原因**：微信开放平台、APP 工程或 OpenSDK 的 Universal Links 配置不一致。
- **处理**：确认登记的 Universal Links 可访问且能拉起 APP；在 `LSApplicationQueriesSchemes` 配置 `weixinURLParamsAPI`、`weixinULAPI`、`weixin`；偶发问题升级微信 OpenSDK 后重试。

#### Xcode 16 打包且 iOS 18 偶现无法拉起微信

- **原因**：老版微信 OpenSDK 使用了系统已废弃的 `openUrl` 接口。
- **处理**：将微信 OpenSDK 升级至 **2.0.4 或以上**。

#### 微信支付后无法返回 APP

- **Android 处理**：在应用包名下创建 `wxapi/WXEntryActivity`，并配置 `android:exported="true"`、`android:taskAffinity="应用包名"`、`android:launchMode="singleTask"`。详见[微信 Android 接入指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/Android.html)。
- **iOS 处理**：确认微信开放平台登记的 Universal Links、URL Schemes 与工程配置一致。详见[微信 iOS 接入指南](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Access_Guide/iOS.html)。

#### 拉起支付报错 `has_no_permission`

- **原因**：商户通常尚未完成微信实名认证，聚合支付交易受到限制。
- **处理**：完成微信实名认证后再发起交易。

#### 取消支付后未返回 APP

- **经验排查方向**：`returnSchema` 未传、与 APP URL Schemes 不一致，或唤起支付使用的 AppId 与开放平台移动应用 AppId 不一致。
- **处理**：确认 `returnSchema` 使用 APP URL Schemes（如 `yourscheme://`），并核对唤起 AppId；返回 APP 后主动查单，不依据取消页面判断交易终态。

#### 报错“商户传入的appid参数不正确”

- **原因**：调用 `wx.requestPayment` 时额外传入或修改了 `appid`。
- **处理**：仅将下单返回的 `timeStamp`、`nonceStr`、`package`、`signType`、`paySign` 原样传入，不额外添加 `appid`。

### 支付宝

#### APP 拉起支付宝小程序报错“交易订单处理失败，请稍后再试”

- **原因**：直接使用下单返回的 `prePayTn`，未编码 `page` 参数或未设置 `thirdPartSchema`。
- **处理**：整体 URL 编码 `page` 参数，并在链接末尾追加 APP URL Schemes：

```text
alipays://platformapi/startapp?appId=...&page=<URL编码后的页面参数>&thirdPartSchema=yourscheme://
```

#### 支付后无法返回 APP 或取不到返回参数

- **iOS 处理**：在 Xcode 的 **TARGETS > Info > URL Types** 配置 URL Schemes，并确保 `thirdPartSchema` 完全一致；拉起链接应以 `alipays://platformapi/startapp?` 开始。
- **Android 处理**：回跳 Activity 配置对应 Scheme、`exported=true`、`launchMode=singleTop`，并在 `onNewIntent` 读取 `code`、`orderAmount`、`customerNo`、`customerRequestNo`、`message`、`status`。
- **风险提示**：支付宝小程序端使用 `open-type="launchApp"` 返回 APP 的方式未见于公开官方 API 文档，存在审核或兼容风险，接入前需自行评估。

#### 支付完成后跳到支付宝首页或淘宝精选，未返回 APP

- **原因**：商户号或服务商可能签约了支付宝“赏金计划”，完成页被引导到活动页面。
- **处理**：取消对应商户号的赏金计划配置；服务商场景通过支付宝服务商平台咨询处理。参见[支付宝赏金计划说明](https://opendocs.alipay.com/admedia)。

#### 回跳 Scheme 错误或取消支付的返回内容始终相同

- **经验排查方向**：`thirdPartSchema` 与 APP URL Schemes 不一致；取消支付也可能没有新的端上返回结果，应用读取到的是上一次页面状态。
- **处理**：先核对 Scheme；取消或返回参数缺失时主动查单，不把端上返回结果作为交易终态。

## 二、小程序内拉起支付

#### 报错“下单失败，请稍后重试”（`code=02004`）

- **经验排查方向**：`payWay`、`marketingProduct` 等参数组合与商户已开通产品能力不匹配。
- **处理**：优先查当前下单接口的业务错误码；小程序场景核对 `payWay=MINI_PROGRAM`，并确认 `marketingProduct` 与签约产品一致。仍无法定位时携带 `orderId` 查询平台日志。

#### 拉起小程序提示“没有体验权限”

- **原因**：目标是体验版小程序，当前微信号不在体验者名单。
- **处理**：正式接入使用正式版：`wx.navigateToMiniProgram` 设置 `envVersion=release`，uniapp `launchMiniProgram` 设置 `type=0`；联调体验版时由小程序管理员添加体验者。

#### 支付完成后再次拉起同一订单，报“已终态”

- **经验排查方向**：部分 Android 机型的完成页回跳异常，页面再次触发同一订单支付；平台以幂等规则拒绝已终态订单。
- **处理**：根据端上返回结果结合查单结果驱动页面流转，避免同一订单重复拉起。

#### 报错 `requestPluginPayment:fail banned in plugin`

- **经验排查方向**：`wx.requestPluginPayment` 不能在插件上下文中调用。
- **处理**：在小程序主包页面发起支付；插件场景改用 `wx.navigateToMiniProgram`，根据下单返回的 `miniProgramOrgId` 和 `prePayTn` 跳转收银台小程序。

#### 小程序 WebView 打开托管 H5 支付链接提示“无法打开该页面”

- **原因**：WebView 只能访问已配置的业务域名，且 WebView 页面不能直接跳转小程序，托管 H5 链路无法在其中完成。
- **处理**：将必要域名配置为小程序业务域名；优先在小程序页面直接拉起收银台小程序，或由 WebView 通过 `wx.miniProgram.navigateTo` 返回小程序页面后再发起支付。

#### 小程序之间跳转后如何读取端上返回结果

- **处理**：在页面 `onShow` 中读取进入参数；`scene=1038` 表示从其他小程序返回，再读取 `referrerInfo.extraData`。物理键返回可能没有 `extraData`，此时主动查单。

```javascript
const options = wx.getEnterOptionsSync();
if (options.scene === 1038) {
  const result = options.referrerInfo?.extraData;
  // result 缺失时主动查单；存在时仅用于页面引导
}
```

`extraData.status` 可能为 `success`、`cancel` 或失败信息，但仍不能独立确认交易终态。小程序拉小程序使用 `launchSource=MINI_PROGRAM`，APP 拉小程序使用 `launchSource=SDK_PAY`。

#### 微信小程序返回 Android APP 时如何识别事件

- **处理**：在 `WXEntryActivity.onResp` 中判断 `resp.type == ConstantsAPI.COMMAND_LAUNCH_WX_MINIPROGRAM`，再从响应对象读取端上返回结果。可对照[微信 Android 拉起小程序示例](https://developers.weixin.qq.com/doc/oplatform/Mobile_App/Launching_a_Mini_Program/Android_Development_example.html)。
